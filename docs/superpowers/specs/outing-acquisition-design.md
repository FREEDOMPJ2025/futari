# Outing Acquisition — 出遊被找到、開始用、帶朋友進來

> 出遊（[group-outing](group-outing-design.md)）是 Futari 唯一會被「非兩人」看到的面。這份 spec 定義它怎麼成為獲客入口：陌生人怎麼搜到它，從它進來的新使用者怎麼開始，朋友怎麼從一個出遊變成使用者。

## 為什麼現在做

2026-10-15 查到的現況：

- **沒人找得到。** 近 90 天整站搜尋點擊約 90 次，幾乎全來自競品名的搬遷頁（manebo、簡單記帳）。`/features/outing` 0 次曝光，GSC 四語都是「Google 不認識這個網址」（#1676）；近 60 天 3 次瀏覽。`llms.txt` 沒提到出遊。站內只有 `use-case/travel`、`use-case/aa-split` 連到它。
- **沒人在用。** prod 總共 2 次出遊、4 個參與者、2 筆支出。
- **量不到。** 資料庫有出遊，但 PostHog 近 90 天 `outing_*` 事件 0 筆。可能是沒人從連結進來，也可能是事件沒送出；現在分不出來。
- **從出遊頁進來的新使用者，第一個畫面是邀請伴侶。** 出遊需要一本帳本，`next=/outings` 在 onboarding 一路上丟失。

使用者的取捨（2026-10-15）：**先增加用戶數**。優先做朋友這條擴散路徑；伴侶邀請的轉換率（60 天 61 次邀請、12 人加入）是另一個問題，不在這份範圍。

## 三件事

### 1. 被找到（SEO／AEO）

出遊頁要搶的不是「分帳 app」這種大字（Splitwise、Tricount 佔著），而是 Futari 出遊真正不同的那一點：**朋友不用下載、不用註冊，一個連結就能一起記**。目標是長尾搜尋與 AI 答案引擎會引用的問句。

- **先被收錄**：首頁功能區、頁尾、`/use-case` 總覽、`/migrate/splitwise` 都連到出遊頁；部署後四語要求建立索引（#1724）。
- **內容要回答問題**：頁首直接回答「怎麼跟朋友分攤旅費、不用每個人都裝 App」，再放一個帶數字的分帳例子（#1725）。不做一批只換名詞的情境子頁——#1676 已經看到 en／ja 的薄頁被檢索過也不收。
- **AEO**：WebApplication JSON-LD、`llms.txt` 出遊段落（#1725）；AI 來源的 referrer 分析在 #1336。
- **分帳品類的搬遷頁**：Tricount／Settle Up（#1060）是出遊的直接對手；日系的 Moneyforward ME／Zaim（#1071）擴大 ja 的入口。兩者都要先查搜尋量再決定來源，新頁要寫厚，避免重演 ja 搬遷頁收錄率低的狀況。

**四語不是直譯。** zh-TW 是主稿；en／ja 的例子與用語要是當地人會搜的說法（例：ja 用「割り勘」）。

### 2. 開始用（意圖保留）

**決定：出遊仍然屬於一本兩人帳本**（[group-outing](group-outing-design.md) 的 epoch 規則不動）。不做「不建帳本就能開出遊」。

從出遊頁進來的新使用者（#1726）：

- 建帳本那一步說清楚原因：「先建好你們的帳本，出遊會記在裡面」。
- 邀請伴侶可以略過，略過不是問題狀態（solo 寫作規則）。
- 建好之後直接到建立出遊，不落在 dashboard。
- 其他入口的 onboarding 不變。

**不採用：** 免帳本開出遊。它會讓出遊脫離章節，動到結束時折回主帳本、離開帳本被進行中出遊擋下等既有規則；Futari 的定位也是兩人優先，出遊是兩人帶朋友，不是獨立的分帳工具。

### 3. 帶朋友進來（擴散）

一個出遊最多 20 人，每個朋友都會打開分享頁。這是出遊最主要的成長迴圈。

- **分享要容易**（#1727）：系統分享面板附預填訊息、當面場合的 QR code、「還有幾個名字沒人選」與再分享的入口。
- **朋友變成使用者**（#1728）：出遊結清之後，分享頁給朋友一張溫和的卡片——你們倆平常的帳也可以這樣一起記。對象是「兩對情侶出遊」裡的另一對。進行中的出遊不顯示，不打斷記帳。

**產品立場：** 分享頁是朋友的工具，不是廣告版位。卡片只在帳記完之後出現一次，可以關掉；語氣是「溫和的見證者」，不用「立即」「開始」「免費試用」，不用感嘆號，不預設對方的性別或感情狀態。分享頁維持 `noindex`、不進 sitemap、OG 預覽不帶出遊內容。

## 測量先行

上面每一件事有沒有效，都要靠事件判斷，而現在的出遊事件很可能是壞的（#1723）。順序：先確認既有發送點在 prod 送得出去，再補 `outing_created`、`outing_link_shared`（帶 method：share／copy／qr）。事件不帶 token、出遊名稱或 URL 內容。

漏斗：

出遊頁瀏覽 → CTA → `signed_up`（`entry_source=feature_outing`）→ `setup_completed` → `outing_created` → `outing_link_shared` → `outing_joined` → `signed_up`（`entry_source=outing`）

**失效的樣子：** 查詢靜默回 0 筆，沒有任何錯誤。看到出遊相關的 0，先在真的瀏覽器走一次、確認事件到了 PostHog，再下「沒人用」的結論（[observability](observability-design.md) 第 0 條）。

## Acceptance

- 四語出遊頁在 GSC 都已收錄，各有至少 3 個站內連結指向它。
- 從出遊頁 CTA 用新帳號登入，三步之內到達建立出遊。
- 在 iPhone 殼、Android 殼、桌面瀏覽器都能分享出遊連結；QR 掃了能進分享頁。
- 結清後的分享頁有卡片，從卡片註冊的人帶 `entry_source=outing`。
- 漏斗每一步在 PostHog 都有事件，URL 屬性沒有 token。
- 四週後（以部署日起算）用同一套查詢比較：出遊頁曝光與點擊、出遊數、從出遊來的註冊數。
