# 離開之後：舊章節與留下的人事物

> 有人離開帳本之後，那段關係留下的紀錄、人、還會動的東西，各自變成什麼。
> 橫切三條離開路徑：自願離開（`leaveGroup`）、被移除（`removePartner`）、刪除帳號（`process_account_deletions`）。

---

## 產品立場

> **章節屬於那段關係，不屬於任何一方。翻頁之後，章節封存——看得到、改不了、不再長大。**
> **事留下，人停在當時，會動的東西停下。**

這延續 [epoch-readonly](epoch-readonly-design.md) 的「故事已經翻頁了 別糾結了 記錯就記錯 記錯也是一種回憶」：回憶不修改，也不刪減。

在這份 spec 之前，三條離開路徑對舊回憶各有一套做法，沒有共同的說法：自願離開把章節拆成兩半、被移除的人完全進不去、刪除帳號把人匿名化但紀錄完整留下。這份 spec 定下共同的立場，三條路徑都以它為準。

### 事（紀錄）：留下、完整、封存

- 已關閉的章節保有那段期間兩個人的全部紀錄：支出、進帳、結算、月回顧留言。
- 誰都不帶走一半，誰都不撕掉。離開不是分家產。
- 章節唯讀（epoch-readonly），離開不會讓任何一方取得修改或刪除舊章節的權力。
- 紀錄的消失只能是使用者明確要求的結果（刪除帳號移除的是個資，不是共同的紀錄），不能是離開流程的副作用。

### 人：停在當時

- 舊章節裡的對方，以「那段時間的那個人」出現：章節關閉時的名字，不顯示頭像，不隨對方之後改名、換頭像而更新。
- 舊章節不連到任何人「現在」的樣子：看不到對方現在的名字頭像、新伴侶、目前的餘額、待確認卡、之後才出現的愛物。反過來，對方回看時也看不到你的現在。
- 這是對兩邊的保護，不是懲罰：留下的人不必看見對方的新生活，離開的人也一樣。
- **刪除帳號是例外**：個資要真的移除，所以在所有章節一律顯示「已離開的夥伴」（見 [account-deletion](account-deletion-design.md)）。
- **離開的人自己要求，也是例外（#1619）**：離開的人可以在「過去的時光」（有帳本的人在設定裡，沒有帳本的人在 `/onboarding/past-times`）按一次，把自己在**已離開的帳本**裡、**當下已關閉**的章節名字，以及那些章節出遊名單上的自己，換成「已離開的夥伴」。
  - 範圍：只動自己的那一格（`GroupEpochs` 的名字快照、`OutingParticipants.display_name`），不動任何人手打的文字（帳本名、交易描述、月回顧留言、出遊或旅行名稱）、匯入檔原始資料、對方已下載的 CSV、加密備份，也不動之後才關閉的章節（一次性，不是持續的設定；之後再離開別的帳本要再按一次）。留下的人、離開後又回到原帳本的人，在那本帳本裡都沒有可改的東西。
  - 單向，不能還原；出遊名單上那格仍是本人的（`profile_id` 不變），只換顯示的名字。離開後才用分享連結以朋友身分加入原帳本之後章節出遊的那格，不在範圍內。
  - 因此「已離開的夥伴」**不再等於帳號已刪除**：它可能只是離開的人自己選擇不留名字。
    - 失效的樣子：沒有任何錯誤；有人看到舊章節顯示「已離開的夥伴」就以為對方刪了帳號，或依此寫出「這個人已刪除」的判斷或文案。
- **「已離開的夥伴」是系統標記，不是名字（#1782）**：刪除帳號、#1619、章節關閉時抄到墓碑，這三種寫入除了寫字面值，也在**同一條 UPDATE** 設標記欄位（`GroupEpochs.member_*_name_is_left_label`、`OutingParticipants.display_name_is_left_label`、`Profiles.is_tombstone`；migration 0099）。
  - **標記是唯一的判斷依據；字面值只是 fallback**（給還沒改的讀取端、部署空窗期的舊程式、手寫 SQL）。讀取端只看標記：標記是 true，顯示讀者語系的 `common.leftPartnerLabel`（已離開的夥伴／已离开的伙伴／a partner who left／退出したパートナー），並用系統樣式（頭像是不含字的中性圓，名字用次要墨色）；標記是 false 就照寫的顯示，就算名字剛好是「已離開的夥伴」也不翻譯、不換樣式。共用 helper 在 `lib/leftPartnerLabel.ts`，翻譯在有 locale 的那一層做（server component、公開出遊頁的 locale、CSV 匯出當下的 locale）。
  - 送到 client 的只有翻好的字串，最多再加一個 `isLeftLabel` 布林；`is_tombstone` 永遠不送。三種來源合成同一個布林，所以畫面不會透露「帳號已刪除」。
  - 失效的樣子：沒有任何錯誤；讀取端拿名字跟字面值比對、而不是讀標記，會把本人取的名字翻譯掉；漏走 helper 的讀取端，英文、日文的讀者會看到繁中的「已離開的夥伴」。
  - 冒充：一般人改不了標記（client 沒有任何路徑寫這四欄），所以樣式是唯一偽造不了的訊號。另外四語的標籤是保留名字（`lib/reservedDisplayName.ts`：改暱稱、出遊加人、免登入加入出遊會被擋，建出遊時抄成員名字與註冊時的 `handle_new_user` 改用預設名字）；形近字（已/己/巳、西里爾字母）擋不住，這是樣式存在的原因。
  - 已知缺口（接受）：0083 之前刪除帳號留下的出遊名單那格，形狀跟成員手動加的訪客一樣，backfill 判斷不了，維持 false，照字面值顯示。dev 上 #1619 的測試寫入同理。
- 舊章節以外的地方另當別論：目前帳本裡仍指向前伴侶的長存物件（愛物、保單、定期規則）屬於「現在」，用「前伴侶」與重新選擇的提示（#1486 / #1579 / #1588 / #1589），不在本節範圍。

### 會動的東西：停下，不追著人跑

- 會在未來產生新事件的東西，在離開的那一刻停住：
  - 離開者的定期規則暫停，未處理的待確認卡清掉（#1588）。已寫入的紀錄、已略過或已確認的卡片不動。
  - 推播不再送給已經不在帳本的人（#1605）。
  - 未接受的邀請作廢。
- 長存物件（房、車、保單）是「物」不是「事」，照既有規則跟著主人走（`leaveGroup` 依 owner；跨帳本的引用指向凍結副本，#1442）。

### 誰能回看

| 離開方式 | 留下的人 | 離開的人 |
|---|---|---|
| 自願離開 | 唯讀回看完整章節 | 唯讀回看他待過的章節 |
| 被移除 | 唯讀回看完整章節 | 唯讀回看他待過的章節 |
| 刪除帳號 | 唯讀回看完整章節，對方顯示「已離開的夥伴」 | 人已不在 |

- 被移除的人跟自願離開的人一樣能回看（2026-10-08 決策）：那段時間也是他的回憶，不因為是被動離開就收回。
- 回看的範圍只有那段章節。進入的是「當時」，不是對方的現在（見上節「人：停在當時」）。

## 不做

- ❌ 「隨時間淡去」的視覺效果（褪色、模糊濾鏡）。模糊用在人與現在的連結上，不用在事上；讓畫面替使用者決定「此刻該感傷」，是品牌準則說的矯情。
- ❌ 離開後修改或刪除舊章節的入口，包括「把我付的那幾筆帶走」。
- ❌ 因為離開而把舊章節的餘額變成可結算的債。舊章節的餘額是已封存的歷史，不是待處理的數字（PRODUCT.md：do not surface a number the user cannot act on）。

## Acceptance criteria

- 任何一條離開路徑之後，留下的人在舊章節看到的紀錄筆數，與離開前在那段章節看到的相同。（自願離開：`__tests__/actions/leaveGroup.keepsChapter1611.test.ts`）
- 自願離開之後，兩本帳本之間沒有任何一筆跨帳本引用；兩個人之後各自刪除帳號都能完成（同上）。
- 離開流程在離開前提供匯出；匯出涵蓋那段章節的支出、進帳與結算，文案就說這三樣，不說「全部」「整本」（#1460）。#1701 之後不再需要「留下的人刪帳號時章節可能跟著刪」的提醒；離開流程文案若仍有這句要拿掉（撤回紀錄見 account-deletion-design）。
- 離開的人（自願或被移除，包含沒有任何帳本的人）之後仍能匯出他待過的已關閉章節（#1460：`__tests__/actions/exportChapterScope.test.ts`）。
- 離開的人（自願或被移除）能從「過去的時光」進入他待過的章節，唯讀，不會被導去登入頁。
- 舊章節的任何畫面，都不出現任何人現在的頭像、之後改過的名字、新伴侶、目前餘額或待確認卡。
- 離開或被移除之後，那個人不再收到原帳本的任何推播。
- 刪除帳號之後，對方在所有章節顯示「已離開的夥伴」。
- 離開的人選擇換掉名字之後（#1619），留下的人在共同章節（過去的時光、月回顧、CSV 匯出）與那些章節的出遊名單上看到「已離開的夥伴」（讀者自己的語系，#1782）；離開的人目前帳本裡的章節不變；再按一次不會再改任何東西，入口也不再出現（`__tests__/actions/hideNameLeftLedgers1619.test.ts`）。
